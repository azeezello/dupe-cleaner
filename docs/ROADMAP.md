# Roadmap

Обоснование решений — в [DECISIONS.md](DECISIONS.md).

## Фаза 1 — точные дубликаты (готово)

- [x] Побайтовые дубликаты среди обычных файлов
- [x] Дубликаты внутри архивов (.zip/.tar(.gz)/.7z/.rar\*) и «вперемешку» с обычными файлами
- [x] Трёхступенчатая воронка (размер → быстрый хэш → полный хэш)
- [x] Карантин с manifest.json, без автоматического удаления
- [x] Отдельная обработка медиафайлов: не уходят в карантин без явного подтверждения
- [x] Персистентный SQLite-индекс: скан переживает падение и не перечитывает то, что уже посчитал
- [x] Прогресс по фазам с процентом, скоростью и ETA; отмена без потери работы; индикатор залипания
- [x] Веб-интерфейс и CLI
- [x] Тесты на сканер, архивы, дедупликацию, карантин, индекс и восстановление после сбоя

\* `.rar` требует внешнюю утилиту `unrar`/`unar` в PATH.

## Фаза 1.5 — что всплыло по ходу

- [ ] Распознавать файлы-заглушки облачных клиентов (Google Drive streaming) и не выкачивать их молча при хэшировании
- [ ] Классификация архива целиком: полностью избыточен / частично / уникален / не прочитан
- [ ] Отдельный список «не проверено» для запароленных и битых архивов — сейчас они попадают только в общие предупреждения
- [ ] Карантин архива целиком при полной избыточности, с предварительной перепроверкой двойников
- [ ] Вложенные архивы (архив внутри архива), ограничение глубины

## Фаза 2 — похожие снимки, лица, альбомы

Порядок важен: каждый шаг опирается на предыдущий.

- [ ] Near-duplicate фото (perceptual hashing, `imagehash`) — разные разрешения, пережатия, лёгкое редактирование одного кадра
- [ ] Выбор лучшей копии внутри группы похожих: разрешение, резкость, отсутствие артефактов пережатия
- [ ] Near-duplicate видео (сэмплирование кадров + агрегированный хэш)
- [ ] Классификация по происхождению: камера / скриншот / мессенджер / скан / загрузка
- [ ] Кластеризация по событиям (разрыв во времени + смена геолокации)
- [ ] Распознавание лиц офлайн, кластеризация по персонам, разметка кластера один раз
- [ ] Подбор названий альбомов по цепочке: геолокация → дата → доминирующее лицо → имя существующей папки
- [ ] Построение библиотеки: перемещение с журналом, XMP-сайдкары с тегами и исходным путём

Всё офлайн, без единого обращения к облачным API — в этом и смысл проекта.

## Фаза 3 — облака

- [ ] Индексация содержимого Google Drive и NAS по метаданным и хэшам
- [ ] Сопоставление локального дерева с облачным тем же движком дедупликации
- [ ] Управляемая синхронизация без скрытых автоматических удалений

## Осознанно не делаем

- **Отдельную очередь «возможно мусор» по качеству.** Качество работает только как выбор лучшей копии внутри группы дублей — см. Р2 в DECISIONS.md.
- **Растворение частично избыточных архивов.** Отложено, сначала только полностью избыточные — см. Р1.
- **Жёсткие ссылки для альбомов.** Не переживают облачную синхронизацию — см. Р5.
- **Перезапись архивов на месте.** Максимальный риск при минимальной выгоде.
- **Мобильное приложение.** Веб-интерфейс покрывает сценарий просмотра с ПК.
