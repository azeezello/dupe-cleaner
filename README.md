# dupe-cleaner

Локальный, приватный инструмент для наведения порядка в файлах на ваших дисках:
поиск дубликатов (обычных файлов **и** файлов внутри архивов), безопасная
работа с медиаконтентом (фото/видео) и — в будущих фазах — авто-организация
фотоальбомов с распознаванием лиц.

Всё выполняется **локально**, без отправки данных куда-либо. Никаких облаков,
никаких подписок.

## Почему

- Годы использования нескольких облаков → переполненные, несинхронизированные
  копии одних и тех же файлов.
- Нужен единый прогон: локальный диск → облака → синхронизация, без риска
  случайно потерять уникальный контент (особенно фото/видео).

## Философия безопасности

1. **Ничего не удаляется напрямую.** Найденные дубликаты перемещаются в
   папку-карантин (`quarantine/`) с сохранением структуры путей и manifest.json,
   описывающим, что и почему туда попало. Окончательное удаление — отдельная,
   осознанная команда/кнопка.
2. **Медиафайлы (фото/видео) — отдельная категория.** Они никогда не удаляются
   автоматически и всегда проходят отдельный ручной review, даже если хэш
   совпал побайтово.
3. **Архив никогда не переписывается; единица действия — архив целиком.**
   Дубликаты находятся и внутри `.zip/.tar(.gz)/.7z/.rar`, но вынуть один
   файл из архива значит пересобрать архив — этого инструмент не делает
   никогда. Вместо этого каждый архив получает один вердикт на весь себя:
   *полностью избыточен* (всё его содержимое уже лежит на диске отдельными
   файлами) / *частично избыточен* / *уникален* / *не прочитан* (пароль,
   повреждение, нет `unrar`). Только первый вердикт даёт право на действие —
   переместить архив в карантин целиком, как один файл, командой
   `quarantine --archives`, и только после того, как каждый двойник на
   диске будет **перечитан и сверён побайтно заново**. Не прочитанные
   архивы попадают в отдельный список «не проверено», а не в общие
   предупреждения: «не смогли заглянуть внутрь» — это не то же самое, что
   «заглянули и ничего не нашли».
4. **Построение библиотеки показывается целиком до того, как что-нибудь
   сдвинется.** `dupecleaner library` печатает план (Р5) и не двигает
   ничего; `dupecleaner build` выполняет его только с явным флагом
   `--move-files-for-real`, только если отпечаток плана совпал с тем, что
   записан в его файле, пишет каждую операцию в журнал **до** её
   выполнения и откатывается одной командой. Единственное удаление в
   проекте живёт здесь: при переезде между томами источник удаляется —
   после того, как хэш копии сошёлся с хэшем источника, и только тогда.
   Подробности и все пять предохранителей — в
   [docs/SAFETY.md](docs/SAFETY.md).

## Статус / фазы

- **Фаза 1 (эта версия, MVP)** — точные (побайтовые) дубликаты: обычные файлы
  + файлы внутри архивов, вперемешку. Карантин + отчёт + веб-интерфейс для
  review. См. [docs/ROADMAP.md](docs/ROADMAP.md).
- **Фаза 2 (в разработке)** — near-duplicate фото/видео (perceptual hashing),
  распознавание лиц, авто-подбор названий альбомов и сортировка фото.
  Архитектура и интерфейсы уже заложены в `src/dupecleaner/media.py`.
  Готова классификация по происхождению (Р3): полный скан помечает каждый
  снимок как камеру, скриншот, сообщение из мессенджера, скан документа или
  загрузку из сети и печатает разбивку. Это метка и будущий фильтр альбомов,
  а не повод что-либо переместить.
- **Фаза 3 (план)** — интеграция с облаками (Google Drive/Photos, Яндекс.Диск,
  OneDrive) для синхронизации без дублей.

Подробности архитектуры: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Модель безопасности: [docs/SAFETY.md](docs/SAFETY.md).

## Установка

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

RAR-архивы дополнительно требуют внешнюю утилиту `unrar` или `unar` в PATH
(чистый Python не умеет распаковывать RAR). ZIP, TAR(.gz/.bz2/.xz) и 7z
работают без внешних зависимостей.

Распознавание лиц — отдельная экстра, потому что это самая тяжёлая
зависимость проекта (OpenCV и numpy, ≈160 МБ на диске) и нужна она не
всем:

```bash
pip install -e ".[faces]"
dupecleaner faces --install-models   # один раз, ≈37 МБ, с проверкой SHA-256
```

Модели (YuNet и SFace, лицензии MIT и Apache-2.0) скачиваются только этой
командой и больше никогда: скан в сеть не ходит. Без них полный скан
отработает как обычно и напишет строкой, что лица не искал. На машине без
интернета файлы можно положить руками и указать папку:
`dupecleaner faces --install-models --source <папка>`. Подробности —
Р11 в [docs/DECISIONS.md](docs/DECISIONS.md).

## Использование

### CLI

```bash
# Быстрый режим (по умолчанию): точные дубликаты среди обычных файлов.
# Внутрь архивов не заглядывает, не строит превью и не считает метрики
# качества — архивы попадают в отдельный список «не проверено в этом
# режиме».
dupecleaner scan D:\Photos D:\Backup\OldPhotos --report report.json

# Полный режим: то же самое плюс содержимое архивов, превью для просмотра
# и метрики качества (разрешение, резкость, признаки пережатия).
# Разница между режимами — только в охвате: в карантин в обоих случаях
# уходит исключительно подтверждённое байт-в-байт.
dupecleaner scan D:\Photos --mode full --report report.json

# Досчитать быстрый скан до полного, не сканируя заново: та же команда с
# --mode full и тем же --db. Уже вычисленные хэши берутся из индекса,
# перечитываются только архивы и недостающие превью.
dupecleaner scan D:\Photos --mode full --report report.json

# Сверить конкретную группу заново — перечитать все её копии и сравнить
# байты прямо сейчас (отчёт мог устареть с момента скана)
dupecleaner verify --report report.json --group <content_hash>

# Переместить подтверждённые группы дублей в карантин (не медиа — по умолчанию).
# На месте остаётся копия в самой осмысленной папке: имя, придуманное
# человеком, важнее папки-даты, а та важнее безымянной свалки вида Pictures\
# (решение Р8 в docs/DECISIONS.md). Остальные копии уезжают в карантин.
dupecleaner quarantine --report report.json --quarantine-dir D:\DupeQuarantine

# То же плюс архивы, всё содержимое которых уже лежит на диске отдельными
# файлами: архив уезжает в карантин целиком, но только после повторной
# побайтной сверки каждого двойника. Любое несовпадение отменяет
# перемещение всего архива.
# Требует отчёта, полученного в полном режиме: быстрый режим внутрь архива
# не заглядывал, поэтому прав на его перемещение не даёт.
dupecleaner quarantine --report report.json --quarantine-dir D:\DupeQuarantine --archives

# Вернуть всё обратно (читает journal.jsonl; архивы возвращаются так же,
# как обычные файлы)
dupecleaner restore --quarantine-dir D:\DupeQuarantine

# Разбить снимки на события: «разрыв во времени плюс смена места» (Р4).
# Только чтение и печать — события ничего не двигают и двигать не могут.
# Нужен полный скан: время съёмки и координаты читаются в его фазе
# метаданных, той же, что определяет происхождение снимков.
dupecleaner events

# Все пороги — аргументы, а не константы. Значения по умолчанию выбраны
# замером на реальной папке (гистограмма разрывов, сверка с вашими же
# папками, таблица чувствительности) — см. claude/task-16-events-report.md.
dupecleaner events --session-gap-hours 9 --place-radius-km 3 --sensitivity

# Второй уровень: соседние события в той же местности как одна поездка.
# Какой уровень станет папкой — открытый вопрос, пока просто показывается.
dupecleaner events --trips --json events.json

# Показать план построения библиотеки (Р5) целиком: каждое перемещение,
# каждый конфликт имён, каждый файл, который спланировать не удалось.
# Ничего не двигает по построению. В конце печатается отпечаток плана.
dupecleaner library --root D:\Library --json plan.json

# Выполнить этот план. БЕЗ ФЛАГА --move-files-for-real это сухой прогон:
# перечитывает диск и говорит, что изменилось с момента плана. Исполняется
# только план, чей отпечаток совпал с записанным в его файле, — то есть
# тот, который вы прочитали.
dupecleaner build --plan plan.json
dupecleaner build --plan plan.json --move-files-for-real

# Откатить построение целиком, по журналу и в обратном порядке. Прерванный
# перенос откатывается так же, как завершённый.
dupecleaner build --rollback --journal D:\Library\_dupecleaner\library-journal.jsonl
dupecleaner build --rollback --journal D:\Library\_dupecleaner\library-journal.jsonl --move-files-for-real

# Разбор собранной библиотеки по одному снимку: что оставить, что
# напечатать, что убрать. Без аргументов — список альбомов и пороги
# печати; с --album — очередь одного альбома, годное первым, с причиной
# одной строкой у каждого снимка и отдельным фильтром «не годится для
# печати» (мегапиксели против формата при 300 dpi).
#
# «Красиво» инструмент не определяет и не пытается: композиция и
# выражение лица не вычисляются, и балла за них нет. Считается арифметика
# печати, следы пережатия, резкость относительно альбома и наличие
# крупного лица в кадре — этого хватает, чтобы отсортировать очередь и
# отсечь заведомо непригодное, и не хватает ни на какой вердикт.
dupecleaner review
dupecleaner review --album "D:\Library\2018\2018 Novosibirsk"

# Применить помеченное «убрать»: перемещение в карантин, не удаление.
# Без --confirm только печатает список и не создаёт даже папку карантина.
# Возврат — той же командой restore, что и для групп дублей.
dupecleaner review --apply --quarantine-dir D:\DupeQuarantine
dupecleaner review --apply --quarantine-dir D:\DupeQuarantine --confirm
```

### Веб-интерфейс (рекомендуется для review, особенно фото/видео)

```bash
dupecleaner serve
# откройте http://127.0.0.1:8765
```

В интерфейсе: переключатель «Быстро / Полно» на экране запуска (по умолчанию
быстрый, с кнопкой «Досчитать полностью» на результатах — без повторного
скана с нуля) и кнопка «Сверить полностью» на любой отдельной группе.
Дальше — запуск скана, просмотр групп дублей с превью изображений,
раздельные списки "обычные файлы" / "медиа, требует ручной проверки" /
"найдено внутри архивов (только отчёт)", кнопка отправки выбранных групп в
карантин.

Отдельный экран — **«Разбор альбома»** (пункт 24): альбом собранной
библиотеки листается по одному снимку и показывается целиком сеткой,
каждый снимок получает одно из трёх состояний с клавиатуры
(<kbd>1</kbd> оставить, <kbd>2</kbd> в печать, <kbd>3</kbd> убрать,
<kbd>U</kbd> отменить, <kbd>G</kbd> переключить вид) или пачкой по всему
открытому списку. Решения пишутся по хэшу содержимого и переживают
перескан, перенос файла и перезапуск сервера. «Убрать» ведёт в карантин —
и только туда: удалить навсегда можно лишь самому, глядя на содержимое
карантина.
